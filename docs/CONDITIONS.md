# 比赛条件与异常记录

这一页记下所有选手的实际参赛条件，以及比赛中的全部中断和事故。

## 赛制

- 10 个模型拿到同一份提示词（`prompt/PROMPT.md`）。每家只有一次写程序的机会，看不到裁判代码，不能试打。
- 交卷后裁判跑 12 局自检（对手全是陪练基准），只查报错、超时、返回值不对、进程卡死，不报胜负。出错时发同一个模板的错误报告（`arena/selfcheck.py`），每家最多 2 次修复机会。
- 8 家通过 Evolink API 调用（单次对话，流式返回，`reasoning_effort: "high"`，`max_tokens` 65536）。
- GPT-6 Astra 在 Gary 的 Mac Pro 上用 Codex 跑（思考档 max），Claude Opus 5.5 在本机 Claude Code 里用一个新开的子代理跑。这是 Gary 10/21 的要求：这两家不走 API。两家都收到同一份提示词，前面多一段说明，要求它们和 API 选手条件一致：不运行或测试代码、不读写文件、不联网、不用工具，直接在回复里交卷（`prompt/HARNESS_NOTE.md`）。
- 通道截断的处理（10/21 05:01 UTC 起执行，对所有选手一样）：如果一次回复没写完就断了（结束原因是输出额度用完、正文为空、或者代码块只有开头没有结尾），这一次作废，不算修复机会，原样重跑；同一档思考强度装不下时，降一档（high → medium → low）再跑。作废的每一次都记在下面的表里，花费照样进总账。这条规则是在 Kimi、Qwen 出现截断之后补上的，之前作废的 Gemini 第一次（主办方上限 32000）也符合这条。Kimi 和 Qwen 之前的记录全部作废，从头重跑，存在 `contest/void/`。

## 正赛

- 70 轮，每轮 121 局：单挑是 11 名参赛者（10 个 AI 加陪练基准）两两之间各打 2 局（换边），55 对共 110 局；大乱斗 11 局，11 名参赛者同场，每轮先按种子打乱座次，再轮转 11 次，每个参赛者每个座位各坐一次。一共 8470 局：单挑 7700 局，大乱斗 770 局。
- 所有局在同一台 Mac mini（12 核）上跑，11 个进程并发。每个选手程序在自己的进程里跑，用 macOS 的 `sandbox-exec` 禁止联网、写文件和启动子进程。
- 时限按选手进程自己的 CPU 时间算（加载 1 秒、第 1 回合 1 秒、之后每回合 50 毫秒），基本不受并发时机器忙闲的影响；墙钟另有 3 秒兜底，超过就结束进程。整场正赛的超时、报错统计见 `results/player-stats.csv`（timeouts、errors、invalid、killed 四列）：Gemini 4 Argon 超时 1 次（它在正赛里一共走了 816,888 步）；Kimi K3 超时 14 次（它在正赛里一共走了 667,327 步），超时的那一回合按规则直行。其余选手没有报错、超时、返回值不对或被结束进程。
- 规则引擎是确定性的：同一个种子加同一串走法，结果永远一样。每局的每一步走法都记在 `results/games.jsonl.gz` 里，可以用 `arena.snake.replay` 原样重放。选手程序里有按 CPU 时间决定搜索深度的，所以同一局重新跑一遍，选手的走法不一定一模一样；片子里的回放用的都是正赛当时记下来的走法。
- 实力值的算法见 `arena/bt.py`：每局按名次拆成两两比较（名次靠前记胜，并列记半胜），单挑和大乱斗两种赛制总权重相等，每对选手加一局虚拟平局，陪练基准 = 0，强 10 倍记 +400，95% 区间用每种赛制内按局重抽样 200 次。
